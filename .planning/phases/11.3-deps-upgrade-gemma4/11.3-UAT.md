## Findings

### D-1: Parakeet models from before the upgrade are reported as "not downloaded" (2026-10-13)

**Observed:** first meeting recording after the upgrade. Every system-audio segment showed `[transcription failed]`; the log repeated `LocalParakeet Code=1 "Parakeet models not downloaded. Please download them from Setup Guide."` from `MeetingRecorder.transcribeClosedBuffer`. Recording, VAD, diarizer micro-windows and meeting save all worked.

**Cause (corrected after the re-download, 2026-10-13):** FluidAudio 0.17 changed the model folder as well as the file set. The old download lives in `~/Library/Application Support/FluidAudio/Models/parakeet-tdt-0.6b-v3-coreml/`; 0.17 looks in the sibling folder `parakeet-tdt-0.6b-v3/` (no `-coreml` suffix) and requires `JointDecisionv3.mlmodelc` there instead of `JointDecision.mlmodelc`. `AsrModels.modelsExist(at:)` therefore returns `false` and `LocalParakeet.loadModel()` throws. Not a migration bug in the app's code; the upstream layout changed. An earlier version of this note guessed the encoder would be renamed to `Encoder_v2.mlmodelc` — wrong: the new folder contains `Encoder.mlmodelc`.

**Resolved by:** downloading Parakeet again from the app. Owner confirmed transcription works afterwards. The streaming EOU models (`parakeet-eou-streaming/160ms`) were not re-downloaded and still work.

**Left behind on disk (checked 2026-10-13):** the re-download does not remove the old folders. Orphaned: `parakeet-tdt-0.6b-v3-coreml/` (461 MB) and `speaker-diarization-coreml/` (13 MB; the diarizer models moved to `speaker-diarization/` the same way, downloaded automatically on first recording). Nothing in the app points at them any more, so "Delete" in Settings will not reclaim that space. On the owner's machine both folders were deleted by hand on 2026-10-13, so the future automatic cleanup cannot be tested against them.

**Defect to fix (not yet scheduled):** the app lets a meeting recording start while the selected STT model is not ready, and surfaces the problem only as `[transcription failed]` per segment. A user upgrading from an older build gets no hint that a re-download is needed. Expected: check STT readiness before starting a recording (and before dictation), and tell the user to re-download Parakeet. A one-time cleanup of the orphaned pre-0.17 folders belongs to the same fix. Still unconfirmed: whether Settings showed Parakeet as "not downloaded" before the re-download.
