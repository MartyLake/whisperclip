**Date:** 2026-10-13
**Method:** local builds of the untouched branch; source inspection of FluidAudio `v0.17.7` and
`mlx-swift-lm` `3.32.3` (shallow clones). Items marked **VERIFIED** were read in source;

## 3. MLX: `mlx-swift` 0.21.2 + `mlx-swift-examples@main` → `mlx-swift-lm` 3.32.3

Package: swift-tools **6.2**, macOS 14; depends on `mlx-swift` `.upToNextMinor(from: "0.32.3")` and `swift-syntax`.
Products used: `MLXLLM`, `MLXLMCommon`, plus `MLXHuggingFace` (macros) for loading.

- **Registry — VERIFIED.** All eleven `LLMRegistry` entries used in `LocalLLM.swift` still exist under the same names. `LLMRegistry.gemma4_e4b_it_4bit` exists (`id: "mlx-community/gemma-4-e4b-it-4bit"`, `extraEOSTokens: ["<turn|>"]`). Model types `gemma4`, `gemma4_unified`, `gemma4_text` are registered.
- **Loading API changed — VERIFIED.** `LLMModelFactory.shared.loadContainer(configuration:)` no longer exists in that form. Model factories now take an explicit tokenizer loader (and a downloader when not loading from disk):
  - `loadContainer(from directory: URL, using tokenizerLoader: any TokenizerLoader)` — matches WhisperClip, which downloads to its own directory first
  - `loadContainer(from downloader:, using tokenizerLoader:, configuration:)`
  - README path: `import MLXHuggingFace`, `import HuggingFace`, `import Tokenizers`, then `#huggingFaceLoadModelContainer(...)`
- **Tokenizer/Hub packages — OPEN (highest risk).** `mlx-swift-lm` 3.x no longer pulls `swift-transformers` transitively; the app must depend on a tokenizer package itself. `mlx-audio-swift` pairs `mlx-swift-lm` 3.32.3 with `swift-transformers` ≥ 1.1.6 and `swift-huggingface` ≥ 0.8.1. WhisperKit 0.12.0 resolves `swift-transformers` 0.1.20 today, so a single graph may not resolve without upgrading WhisperKit (latest 1.1.1). Plan 01 settles this before any source is touched.
- **`import Hub` in `ModelDownloader.swift` — OPEN.** `HubApi(downloadBase:)` / `hubApi.snapshot(...)` came transitively through `mlx-swift-examples`. After the migration it must come from an explicit dependency; its API in `swift-transformers` 1.x has to be checked.
- **Loading from a directory — OPEN.** `LocalLLM.loadModel` currently takes a registry configuration and overrides `id = .directory(path)`, which keeps per-model settings such as `extraEOSTokens`. `loadContainer(from: URL, ...)` builds a bare `.init(directory:)` configuration. Check whether a registry configuration can still be combined with a local directory; if not, the Gemma 4 `<turn|>` EOS token must be handled explicitly.
- **Generation — partially verified.** `UserInput(chat:additionalContext:)` and `GenerateParameters(maxTokens:temperature:)` still exist. `MLXLMCommon.generate(input:parameters:context:)` returning an async stream with `.chunk` was not re-read — confirm at compile time.
- `MLX.GPU.set(cacheLimit:)` exists in 0.21.2; confirm it is not deprecated in 0.32.x.

## 4. Gemma 4 E4B

- Weights: `mlx-community/gemma-4-e4b-it-4bit` (same repo Radnyk uses with Python `mlx-lm`).
- `LLM.swift` has Gemma-2-specific handling: system prompt folded into the user prompt, and a trailing `<end_of_turn>` stripped. Gemma 4 uses different turn markers (`<turn|>`) and may accept a system role — decide by reading the model's chat template, then verify on real output.
- Radnyk patched the chat template only for tool responses; WhisperClip does not use tools, so that patch is not expected to be needed.
- Caution: an Apple Developer Forums thread from spring 2026 reported Gemma 4 unsupported in `mlx-swift-lm` 2.31.x and prompt corruption via swift-jinja 1.x. Support is present in 3.32.3, but output quality must be checked by eye, not assumed.

## 5. Build scripts

`build.sh` and `build_dev.sh` copy `mlx-swift_Cmlx.bundle` from `Build/Products/Release/`. The resource
bundle name can change with the `mlx-swift` upgrade — list the products directory after a Release build.
`local_build.sh` uses `xcodebuild -scheme WhisperClip` in the repo root and must keep resolving to
`Package.swift` (the generated Xcode project lives in `Xcode/` for this reason; a `WhisperClip.xcodeproj`
in the repo root breaks it).
