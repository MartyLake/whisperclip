|---|---|---|---|---|---|

## 2. FluidAudio API — VERIFIED (read in source)

```swift
// Diarizer/Nemotron3/Nemotron3Types.swift
public struct Nemotron3Config: Sendable {
    public static let fast, fast24, fast32, fast128, low, veryLow, ultraLow, efficient, offline
    public static func preset(named: String) -> Nemotron3Config?   // "fast32", "fast32-int8", "fast32-split-w8a8", …
    public let numSpeakers = 8, sampleRate = 16000
    public var outputFrameSeconds: Float { 0.01 }
    public var chunkSeconds: Double; public var latencySeconds: Double
    public var modelFileName: String; public var hubSubdirectory: String
}
public struct Nemotron3ChunkResult: Sendable {
    public let probabilities: [Float]   // frameCount * numSpeakers, row-major by frame
    public let frameCount: Int; public let numSpeakers: Int
}
public struct Nemotron3Segment: Sendable { speakerIndex, startSeconds, endSeconds }
public enum Nemotron3Error: Error, LocalizedError { modelLoadFailed, inferenceFailed, invalidState }

// Diarizer/Nemotron3/Nemotron3Models.swift
public static func load(config:, directory: URL, computeUnits: MLComputeUnits = .all) async throws -> Nemotron3Models
public static func loadFromHuggingFace(config:, cacheDirectory: URL? = nil, computeUnits: = .all,
                                       progressHandler: ProgressHandler? = nil) async throws -> Nemotron3Models

// Diarizer/Nemotron3/Nemotron3Diarizer.swift — "This class is not thread-safe."
public final class Nemotron3Diarizer {
    public init(config: Nemotron3Config, models: Nemotron3Models)
    public func reset()
    public func appendAudio(_ samples: [Float])                       // 16 kHz mono
    public func processBufferedAudio() throws -> [Nemotron3ChunkResult]
    public func finishStream() throws -> [Nemotron3ChunkResult]       // flush tail; reset() before reuse
    public private(set) var streamedFrameCount: Int                   // 10 ms frames emitted so far
    public static func segments(probabilities:, frameCount:, numSpeakers: = 8, threshold: Float = 0.5,
                                frameSeconds: Float = 0.01, minDurationSeconds: Float = 0.2) -> [Nemotron3Segment]
}
```

Facts that shape the design:
- Speaker slots are "ordered by first arrival" and persist for the stream — stable labels with no clustering.
- Output is per-frame probability per slot: overlap is representable, silence is "no slot above threshold".
- Synchronous inference, not thread-safe, not `Sendable` → must live inside one actor.
- `appendAudio` after `finishStream` is a `precondition` failure (crash) unless `reset()` was called.
- `loadFromHuggingFace` downloads only the requested preset, stores under
  `~/Library/Application Support/FluidAudio/Models/<Repo.nemotron3Diarization.folderName>/`, discards a
  cache from an older weights version, and writes a weights-version marker when complete.

## 3. Open questions

- **Cache folder name.** The doc comment says `nemotron-3-diarization/…`, `ModelNames.swift` maps the
  repo to `nemotron-3-diarization-coreml`. Take the path from `Repo.nemotron3Diarization.folderName`
  (if public) or from what appears on disk after the first download; never hard-code a guess. Finding
  D-1 in Phase 11.3 came from exactly this kind of folder assumption.
- **Existence check without loading.** There is no `modelsExist` for Nemotron 3. Mirror the library's
  own completeness test: `<bundle>.mlmodelc/coremldata.bin` plus `learnable_sil_emb.bin` plus the
  weights-version marker. Check whether `ModelNames.Nemotron3` constants are public.
- **Per-chunk cost on this machine.** 179x real time is an M5 Pro figure. Measure
  `Nemotron3Diarizer.lastProfile` / wall time per `processBufferedAudio` call during the manual pass;
  if a 2.56 s chunk takes more than ~0.5 s, speech-to-text and the diarizer will contend.
- **`computeUnits`.** `.all` is the default. Parakeet and WhisperKit also use the Neural Engine; watch
  for contention with live transcription in the manual pass.
- **Threshold and smoothing.** `segments(...)` defaults: threshold 0.5, minimum 0.2 s. Radnyk
  post-processes frames into turns in Python — compare its thresholds and gap-merging before choosing.
- **Continuity of time.** The diarizer's clock is the count of samples appended. If system-audio
  capture ever skips (no callbacks during silence, device change), timeline time drifts from recording
  time. `SpeakerBufferManager.onAudioBatch(_:atTime:)` receives a timestamp — gaps must be padded with
  zeros so both clocks stay aligned.

## 4. What exists in the app today

- `DiarizationProvider.diarize(samples, sampleRate:, atTime:) -> DiarizationResult` — chunk in, segments out.
- `SpeakerBufferManager` (actor): polls every 150 ms, re-diarizes the whole accumulating window, takes
  the dominant speaker, splits on change, flushes 7 s micro-windows, 30 s cap, 0.5 s minimum, maps
  `SPEAKER_00` → "Speaker 1". Fires `onSpeechDetected(startTime, label)` on every poll with speech.
- `MeetingRecorder`: builds `DiarizerManager` + `DiarizerModels.load()` at recording start and falls
  back to a source-based system buffer if that throws. `transcribeClosedBuffer` and
  `handleSystemSpeechDetected` consume the manager's output.
- `ModelStorage` / `OnboardingView`: download, size and delete for the old diarizer models
  (`DiarizerModels.downloadIfNeeded()`), stored in `FluidAudio/Models/speaker-diarization/`.
- Tests: `SpeakerBufferManagerTests` and `DiarizerMicroWindowTests` (15 test methods) with
  `MockDiarizationProvider` built on `DiarizationResult` / `TimedSpeakerSegment`.
- There is no Keychain or token code anywhere in `Sources/`.
