  <name>Task 1: TranscriptGrouping</name>
  <files>Sources/TranscriptGrouping.swift, Tests/TranscriptGroupingTests.swift</files>
  <action>
- `struct TranscriptGroup: Identifiable` — `id: UUID` (first segment), `speaker: Speaker` (group key; `.pending`
  for a pending-only group), `segments: [MeetingSegment]`, computed `startTime`, `endTime`, `isMe`,
  `isPendingSpeaker` (key is `.pending`), `hasTypingTail` (last segment pending with empty text).
- `enum TranscriptGrouping { static func groups(from segments: [MeetingSegment], maxGap: TimeInterval = 30) -> [TranscriptGroup] }`.
  Input is assumed sorted by `startTime` (as `liveTranscript` and stored segments are); do not re-sort.
- Rules, in order, per segment with `key = segment.displaySpeaker`:
  - no current group → open one;
  - gap `segment.startTime - previous.endTime > maxGap` → open one;
  - `key == .pending` and current group is not Me → append (D-05);
  - `key == current.speaker` → append;
  - current group is a pending-only group and `key` is not Me → the group takes `key` and the segment is
    appended (a resolved first row turns its pending group into that speaker's group);
  - otherwise open one.
- Tests (build `MeetingSegment`s directly, no session/storage):
  same speaker merges; Me interjection splits Other/Speaker turns; `.labeled("Speaker 1")` vs `"Speaker 2"`
  split; pending after Speaker 1 joins it; pending after Me opens a pending group; resolved-later re-group
  (mutate `speaker`/`isPending`, regroup, assert split into a new group with a new id while the first group
  keeps its id); gap > 30 s splits; mic pending row stays in Me group; empty input → empty output;
  `hasTypingTail` true only for an empty pending last row.
  </action>
